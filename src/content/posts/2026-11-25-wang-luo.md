- 为什么不用--link?link的做法是:把被 link 容器的信息注入成一组环境变量(形如 <别名>_PORT_*),同时改写目标容器的 /etc/hosts
  1. 写死的信息不会更新。源容器重启后 IP 可能变化,而环境变量里的 IP 不会自动跟着更新。
  2. 它绑死在默认 bridge 上。link 只在默认 bridge 有意义,而默认 bridge 本身已被官方视为 legacy

# bridge：docker默认网络模式
默认bridge容器间只能通过ip相互访问，自定义bridge自带一个dns可以按容器解析，对外dns解析则直接转发给宿主配置的dns
- 自定义bridge
  ```bash
  创建网络
  docker network create appnet
  加入网络
  docker run -d --name web --network appnet nginx
  docker run -d --name client --network appnet alpine sleep 3600
  ```
  - 自动服务发现即上面说的自带dns只解析--name指定的名字，不解析docker随机生成的名字
